# Crashes on the Mac, 2026-11-20

Three panics in `terminal_host` in one session of the release Fyx Dev build on the owner's Mac
(macOS, aarch64), with `fyx-claude-code` enabled from `target/fyx-demos-v0_4`. All three are the
same kind: an entity or window is read or updated while gpui is already updating it. Fixes are on
`fyx/profile-menu-crash`.

Stacks are from the macOS crash reports, symbolicated with `atos` against the build's
`fyx.dwarf` and demangled with `llvm-cxxfilt`. Only Fyx, Zed and gpui frames are kept; std, core,
alloc, the panic machinery and the executor are dropped. Line numbers are those of the build named
under each crash. Crash 1 and 2 were read from atos's output before the next build replaced the
`.dwarf`, so their frames are listed as read then (by function, with lines where atos gave them).

## Why the tests missed them

`terminal_host`'s tests run without `TrustedWorktrees`, without a `MultiWorkspace` window and
without docks, so none of these handlers runs inside a real window update. Its `Cargo.toml` has no
`workspace`/`project` test-support dev-dependencies. `WindowHandle::root` exists only with gpui's
`test-support`, so code using it passed `cargo nextest` and `./script/clippy` and failed the
release build: check `cargo check -p <crate>` without test cfg as well.

## What to look for elsewhere

In every click or action listener, `subscribe`/`subscribe_in`/`observe` callback and notification
handler of the Fyx crates (`terminal_host` first, then `ui_ext_host`, `agent_review`,
`terminal_ext` and the `fyx:` hooks):

- `cx.windows()` followed by `read_with`/`update` on each handle, when the caller may run inside one
  of those windows;
- `Entity::read`/`update` of a view, panel or window that may be the one being updated (the
  subscriber's own view, the listener's own panel);
- `focus_panel`, `activate_item`, dock or pane changes, or reveal-style helpers called
  synchronously from inside a panel or a view's subscription.

Fixes that worked here: pass the current `Window` and read it directly; read the model (`Terminal`)
instead of the view; defer with `window.defer` or `cx.defer`.
