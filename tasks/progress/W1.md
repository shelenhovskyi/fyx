# W1 progress (rebrand and de-cloud)

State: done and verified on Windows 11 (2026-11-17). No request leaves the machine at startup.

## Design

- **Brand and identity** come from existing knobs, so the upstream diff stays small:
  - `paths::APP_NAME = "Fyx"` (the constant upstream documents as "forks should change this"):
    `%APPDATA%\Fyx` (config), `%LOCALAPPDATA%\Fyx` (data, logs, db), `~/.config/fyx`,
    `$XDG_DATA_HOME/fyx`, `~/Library/Application Support/Fyx`, log file `Fyx.log`.
  - The `zed` crate's binary is now **`fyx`** (`crates/zed/Cargo.toml` `[[bin]]` and
    `default-run`): upstream's `main.rs` asserts at compile time that `APP_NAME` matches the
    binary name. The package is still `zed`, so `cargo build -p zed` / `script/gate.sh` are
    unchanged; the output is `target/debug/fyx.exe`.
  - `release_channel`: `display_name()` → `Fyx` / `Fyx Dev` / …, `app_id()` → `dev.fyx.Fyx`
    (`-Dev`, `-Nightly`, `-Preview` suffixes like upstream), `app_identifier()` (Windows) →
    `Fyx-Editor-<Channel>`, which names the single-instance mutex and the named pipe.
  - `crates/zed/src/main.rs` calls `cx.set_app_identity(app_id, display_name)`, so the Windows
    AppUserModelID is `dev.fyx.Fyx` (taskbar grouping, toasts) rather than one derived from the
    exe path. Upstream never called it.
  - `crates/windows_resources`: exe version info `ProductName`/`FileDescription` = `Fyx Dev`,
    `CompanyName` = `Fyx contributors`. `LegalCopyright` (Zed Industries) stays: it is a
    copyright notice, not branding.
  - Product name in `crates/zed`: app menu (`Fyx`, About/Hide/Quit Fyx), About window title,
    "Fyx failed to launch", HTTP User-Agent `Fyx/<version> (<os>; <arch>)`.
- **URL scheme `fyx://`**: `client::ZED_URL_SCHEME = "fyx"` (what macOS registers at runtime), the
  Windows installer registers `HKCU\Software\Classes\fyx` (`zed.iss`). Inside the app `zed://`
  stays the internal link namespace (mentions, schemas, settings links: ~40 call sites), so an
  incoming `fyx://…` is rewritten to `zed://…` at the two entry points: CLI args in `main.rs`
  (covers the first instance and forwarding over the pipe) and `OpenRequest::parse`
  (`open_listener.rs`, OS open-URL events). Helper: `zed::fyx_url_to_internal`.
- **De-cloud through settings, not code**: new `assets/settings/fyx.json`, layered over Zed's
  untouched `default.json` by `fyx_default_settings` in `main.rs` right after `settings::init`.
  `default.json` is not edited: it churns upstream (rebase conflicts) and upstream tests read it
  (the `extensions_ui` suggestion tests would break, for one). Contents:
  - `server_url: "http://127.0.0.1:0"`. Every zed.dev URL (`api.`, `cloud.`, `llm.`, `/rpc`,
    extension registry, telemetry, auto-update, account pages) is derived from it in
    `HttpClientWithUrl::build_*_url`; port 0 fails at `connect()` before a packet is sent.
    `ZED_SERVER_URL` still overrides it, and `"https://zed.dev"` in user settings restores Zed's
    services (their terms apply).
  - `telemetry.diagnostics/metrics: false`, `auto_update: false`.
  - `title_bar.show_sign_in/show_onboarding_banner: false`, `collaboration_panel.button: false`.
  - `edit_predictions.provider: "none"` (the `zed` provider needs a zed.dev account).
  - `auto_install_extensions.html: false`, `suggest_extensions: false` (no registry by default;
    whether Fyx may use Zed's registry is an open owner decision in `PLAN.md`).
  - Objects merge key by key, so `fyx.json` turns entries off rather than removing them.
- **`client` is neither deleted nor stubbed in code**: with `server_url` pointing nowhere it never
  connects; `project`/`workspace`/collab compile unchanged. Crash upload needs
  `ZED_MINIDUMP_ENDPOINT` (unset) and `diagnostics` (off). BYO-key providers and ACP agents are
  untouched.

## Product-name sweep (second W1 task, 2026-11-17)

Scope: every place a user can see "Zed" as the product name. Inventory method: a scanner
(`scan_zed.py`, kept out of the repo) listed every non-test Rust string literal containing the
word `Zed` (214 hits in 45 crates), plus `--help` doc comments, the installer and default
settings. Each hit was classified below. Every changed line carries a `fyx:` marker (on its own
line where a trailing comment would change rustfmt's output or end up in `--help`).

**How the name is sourced.** Where one function renders many strings, the name comes from one
place: the extension-page upsell banners (18 strings, "… is built-in to Zed!") go through
`render_feature_upsell_banner`, which now substitutes `ReleaseChannel::Stable.display_name()` ("Fyx"). Identity names come
from `release_channel` (`display_name()`, `app_id()`, `app_identifier()`) and `paths::APP_NAME`
(first W1 task). Elsewhere each string is a static literal with no shared funnel, so it is
changed in place: referencing a constant would touch the same line, turn `&'static str`
literals into `format!` calls, and add `paths`/`release_channel` dependencies (and Cargo.lock
churn) to crates that lack them. The replacement is one line per string.

## Handoff (terminal stream)

### Crate layout (approved by the coordinator)

- `crates/terminal_ext` (leaf: alacritty_terminal, gpui, base64, percent-encoding, polling, rand). `crates/terminal` and
  `crates/terminal_view` depend on it, so it must never depend on terminal, terminal_view, project, workspace or ui_ext.
  - `tee_pty.rs`: `TeePty<P: EventedPty>`, `type Reader = Self`. It scans reads (`osc_scan.rs`, ends like vte, 8 KiB cap), answers
    `7501;?` with the constant `program_status::REPLY` through the event loop channel, parses (`osc.rs`), applies state
    to `status.rs` and queues into `inbox.rs`. On `ChildEvent::Exited` it drops working/blocked records.
  - `terminal_id.rs`: `TerminalExt` (upstream `Terminal::fyx`), `TerminalId`, `TerminalToken`, `terminal_for_token()`,
    `status()`, `clear_attention()`, `take_osc_events()` (drain on the Terminal's `Wakeup`; alacritty sends one after every read).
  - `osc.rs`: `OscEvent` for 7, 9, 9;4, 9;9, 99, 133, 633 (A-D, E with nonce, P;Cwd), 777;notify, 1337 SetUserVar and 7501
    (all rev 0.4 limits). `clean_text` strips control, bidi and invisible-format characters.
  - `inbox.rs`: 256-entry queue; state events coalesce by key. Rates: notify 4/s (burst 8), shell 64/s, state 64/s,
    query replies 2/s (burst 4).
  - `status.rs`: `TerminalStatus { state, kind, label, detail, progress, attention, source, updated }`. The shown record is the most urgent of
    blocked > error > working > done > idle. Attention is set on entering blocked, done or error, on a notification, or on 9;4 error.
    `StatusSource::Program { protocol, app }` with `describe()` gives "Claude Code via OSC 7501".
  - `decorations.rs`: `TerminalDecorations` global (`set_decorations`, `tab_indicator`).
- `crates/terminal_host` (gpui, ui, terminal, terminal_view, terminal_ext; later workspace, project and ui_ext[t2]).
  - `tab_status.rs`: draws the icon (working spins, blocked warning, error, done check, idle nothing), an attention dot and
    a tooltip whose meta always ends with the source. Attention clears on focus-in and on Wakeup while focused.

### Decisions and findings
