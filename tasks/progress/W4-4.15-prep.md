# W4 prep for plan 4.15: canvas in the SDK, the harness and a demo

Prep only; nothing is built yet.

- Source: `docs/fyx/wit-0.3/design.md` §13 and the staged WIT
  (`crates/ui_ext/wit/since_v0.3.0/fyx-ui.wit`: `canvas-props`, `draw-op`, `canvas-click`).
- Plan row: `docs/fyx/platform/plan.md`, 4.15, which depends on 4.13.
- Priority: the canvas ranks last in P4 and moves to 0.4 if P4 slips (owner's rule, 2026-11-18).
  Nothing here should start before 4.13 lands or before the higher P4 work is done.

## 1. What 4.15 needs from others

| From | What | Why W4 waits for it |
|---|---|---|
| 4.13 (W2c) | `Props::Canvas(CanvasProps)` in the `ui_ext::v0_2` model, the `DrawOp` family, `UiEvent::CanvasClick`. Shared validation in `ui_ext` for the §13 caps (16384 ops, 65536 segments, 256 KiB of text, finite coordinates within ±32768, strokes 0.5 to 16, description 1 to 1024 bytes) and for placement (panel trees only, not list rows; 16 per surface) | The harness converts into that model and checks with those functions, as for images (D6). Without them it can only keep refusing canvas as "not supported yet", as it does today |
| 4.13 (W2c) | How the host counts a canvas toward the per-call lifted-text cap: the description plus every text op, as I assume | `props_text_len` must match, or the harness drifts from the host |
| 4.13 (W2c) | Canvas cases in `fixtures/probe_v0_3`, like the image cases | `harness_conformance_v0_3` compares them |
| 4.14 (W3) | The renderer's hit-test mapping (`scale-down`, scroll) | Only for the "demo runs in Fyx" half of the done criterion; the headless half needs nothing from W3 |

The SDK already has the 0.3 bindings for all of it, behind `fyx-ui-0-3`. The 0.1 and 0.2
down-conversions already refuse a canvas node ("needs fyx:ui 0.3"). `SurfaceTree::apply_event`
already handles `canvas-click`.

## 2. SDK (`crates/ui_ext_sdk`, `fyx-ui-0-3` only)

Charts are built in loops, so the draw list is a `&mut self` builder, not a chain of owned
values:

```rust
let mut draw = DrawList::new();
draw.rect(Rect::new(0.0, 0.0, 240.0, 120.0), Some(Paint::token(ColorToken::ElevatedSurface)), None);
for (index, value) in values.iter().enumerate() {
    draw.rect(bar(index, *value), Some(Paint::data(DataColor::cycle(index))), None);
}
draw.path(Path::new().move_to(pt(0.0, 90.0)).line_to(pt(30.0, 40.0)).stroke(Stroke::new(Paint::token(ColorToken::TextAccent), 1.5)));
draw.text(pt(4.0, 14.0), "Commits per day", Paint::token(ColorToken::TextMuted));
let canvas = CanvasProps::new(240, 120, "Commits per day, Monday to Sunday")
    .draw(draw)
    .clickable()
    .fit(CanvasFit::ScaleDown);
tree.canvas(canvas);
```

- **Values:**
  - `pt(x, y)` / `Point::new`, `Rect::new(x, y, w, h)`;
  - `Paint::token(ColorToken)` and `Paint::data(DataColor)`, opaque by default, with
    `.opacity(percent)`;
  - `Stroke::new(paint, width)`;
  - `DataColor::cycle(index)`, the "data-color helper" of §13 tests: series 1 to 8, repeating.
- **`DrawList` ops:** `line`, `rect`, `rounded_rect`, `circle`, `path(Path)` and `text`. Each
  returns `&mut Self`. `text_with(at, text, paint, TextStyle { size, anchor, monospace })` covers
  the rest.
- **`Path` builder:** `move_to`, `line_to`, `quad_to`, `cubic_to`, `close`, then `fill` and/or
  `stroke`.
- **`DrawList` accessors:** `len()`, `segments()` and `text_bytes()`, so an extension can see how
  close it is to the caps.
- **`CanvasProps::new(width, height, description)`:** not clickable, `clip`. Setters:
  `.draw(DrawList)`, `.clickable()` and `.fit(CanvasFit)`. Also `From<CanvasProps> for Props` and
  `TreeBuilder::canvas`.
- **`CanvasHits`**, an optional hit-test helper, because hit-testing is the extension's job:
  - `hits.add(rect, value)` records a region;
  - `hits.at(x, y) -> Option<&V>` returns the topmost (last added) match;
  - it is built next to the draw list, so a bar chart gets click-to-select in three lines.
- **Checks before the host:** `SurfaceTree` runs `ui_ext`'s canvas validation on mount, insert,
  set-props and rebuild, as it does for tree limits. A bad canvas then becomes a `TreeError` in
  the extension instead of a rejected update.
- **Docs:** a canvas section in `sdk-reference.md` (builders, caps, no text measurement: position
  labels with the anchor) and the limits in `limits-and-gotchas.md`.

## 3. Harness (`crates/fyx_ext_harness`)

- **v0_3 conversions:** `wit::CanvasProps` and `draw-op` become the model types, and
  `unsupported("a canvas node")` goes away. `UiEvent::CanvasClick` converts both ways.
- **Checks at apply:** the shared `ui_ext` canvas validation and placement, like
  `check_images`. That includes the 16-per-surface cap, counted on the tree after the update
  applies, which is where the host counts it.
- **`props_text_len`:** the description plus the text ops, once W2c confirms the host counts the
  same (§1).
- **`begin_event`:** `canvas-click` grants the click-or-Enter activation (Q13, decided).
- **`Harness::canvas(surface, node) -> Option<&CanvasProps>`** gives tests the draw list to
  assert on: op counts, colours, the selected bar's stroke.
- **`Harness::canvas_click(surface, node, x, y) -> Result<Outcome>`** clicks as the renderer
  would. It fails, without a call, when:
  - the node is not a canvas;
  - the canvas is not `clickable`;
  - the point is outside `0..width` × `0..height`, which the renderer never sends.
- **Conformance:** `harness_conformance_v0_3` gains W2c's canvas probe cases: accepted pushes,
  each cap, NaN, placement, and replies on a panel, a status item and a modal.
- **`fyx-ext test` smoke run:** mounting already validates canvases. Nothing new.

## 4. Demo: `extensions/fyx_demo_charts`

A new workspace member, which needs W0's approval as an integrator line.

- **Panel "Charts"** (left dock), 0.3 only. The default 0.1 build shows "needs fyx:ui 0.3",
  as `fyx_demo_images` does.
  - **Bar chart:** seven days of mock values, bars in `DataColor::cycle`, axis lines in
    `Border`, labels anchored `middle`, and `clickable`. A click selects a bar through
    `CanvasHits`: it draws the selected bar with a `TextAccent` stroke, and a text node below
    reads `Wed: 42 commits`.
  - **Sparkline:** a 60-point path that a 500 ms tick moves along, with a Pause/Resume button.
    The tick is re-requested only while running. The host pauses it while the panel is hidden
    (0.2 §B).
  - **`scale-down`:** the chart keeps its aspect ratio when the dock is narrow.
- **Manifest:** `capabilities = ["ui:panel", "ui:canvas"]`, `api_version` 0.1.0.
  `fyx-build-demos --fyx-ui-0-3` already produces the 0.3 package.
- **Tests:**
  - SDK-only unit tests: the bar geometry, the hit regions, and the sparkline window.
  - Harness tests through `load_package`: a click on a bar selects it; a click outside the bars
    selects nothing; `canvas_click` outside the box is an error; three ticks move the sparkline
    and keep the op count fixed; Pause stops the ticks.

## 5. Decisions to make (my recommendation first)

1. **Shared canvas validation lives in `ui_ext`** (W2c, 4.13), as D6 did for images. The SDK,
   the harness and the host all call it. *Alternative:* each checks itself, which drifts.
2. **`DrawList` as a `&mut` builder,** with `CanvasProps::draw(list)`. *Alternative:* chained
   owned methods on `CanvasProps`. These read well for three ops and badly in a loop.
3. **The SDK validates canvases before the host** (in `SurfaceTree`). *Alternative:* leave it
   to the host. An extension then learns about a NaN only from a rejected update and a resync.
4. **`canvas_click` outside the box or on a non-clickable canvas is a harness error,** not a call.
   It mirrors what the renderer can send, as `notification_action` does for unknown actions.
5. **No raster snapshots in the harness:** paint belongs to the renderer, so tests assert on draw
   lists. *Alternative:* a software rasterizer in the harness, which would be a second renderer
   to keep in step.
6. **Demo name `fyx_demo_charts`,** one crate for both the bar chart and the sparkline, per the
   plan row. *Alternative:* two demos, which is more manifests for the same API.

## 6. Order of work once 4.13 lands

1. The SDK value types and `DrawList`/`Path`/`CanvasProps` builders, `TreeBuilder::canvas`, and
   `CanvasHits`, with unit tests. These need only the bindings, so they can start before 4.13's
   model if needed.
2. `SurfaceTree` validation through `ui_ext`, once 4.13's checks exist.
3. The harness: conversions, checks, `canvas`, `canvas_click`, and the conformance cases.
4. The demo, its harness tests, then docs and the generated API pages.

Size: about the same as 4.12 without the version plumbing. The SDK part is mostly builders.
