## How it works

- `decorations::init` (called from `ui_ext_host::init`) sets a global `Entity<Decorations>` and
  observes every new full-mode `Editor`. Each editor syncs its blocks when the decorations change
  and on `BufferRangesUpdated`, `BuffersRemoved`, `TitleChanged`, `Saved`.
- A decoration names a path (absolute, or a component suffix of the worktree-qualified path) and
  a zero-based row. The first time a buffer for that path shows up, the row becomes
  `buffer.anchor_after(Point::new(row, 0))`, stored per `BufferId` in the decoration. Right bias:
  a line inserted at the start of the decorated line pushes the anchor down with it (the test
  fails with `anchor_before`, checked). Editors map it with `anchor_in_excerpt`, so multibuffers
  work too.
- The tree lives in a `SurfaceState` (the panel machinery; `add` takes any `UiBackend` + surface,
  `add_tree` a static tree whose updates are written back so a remount keeps them) and is drawn by
  one `SurfaceView` per editor inside a `BlockStyle::Sticky` block, indented by the gutter. Theme
  tokens only, no extension call while rendering.
- Height: `DecorationTarget::lines`, or estimated from the tree (columns add, rows take the
  tallest), clamped to 1..=40 lines; updates that change it resize the block.

## Tests (`crates/ui_ext_host/src/decoration_tests.rs`)

- `test_block_follows_its_line_through_edits_above` (primary evidence): `scratch/notes.txt` in a
  `FakeFs` project, block under row 2 → display row 3. Two lines inserted at the top → row 5; a
  line typed at the start of the decorated line → row 6. The drawn text (`fyx-node-2` debug bounds)
  moves down by exactly two line heights, then one. Edits below and on the line leave it at 6. A
  second editor opened after the edits puts its block at row 6 too (same anchor). `remove` takes
  the blocks out of both editors and the text is no longer drawn.
- `test_updates_repaint_and_resize_the_block`: an `above` decoration; a `set-props` to a two-line
  text grows the block from 1 to 2 lines (the next buffer line moves from display row 2 to 3).
- `test_other_files_get_no_block`, `test_path_matching`, `test_estimated_lines`,
  `test_dev_file_format`.

## Dev data source

```jsonc
// FYX_UI_DEV_DECORATIONS=<path of this file>
[
  // `line` is 1-based, as in the gutter.
  { "path": "scratch/notes.txt", "line": 3, "text": "a note under line 3" },
  { "path": "notes.txt", "line": 1, "placement": "above", "lines": 2,
    "nodes": [ { "id": 1, "parent": null, "props": { "text": {
      "content": "tree\nform", "color": "warning", "bold": true, "monospace": false } } } ] }
]
```

Read once at startup; errors go to the log (`fyx:ui: FYX_UI_DEV_DECORATIONS: ...`), success logs
`fyx:ui: loaded N dev decoration(s)`.
