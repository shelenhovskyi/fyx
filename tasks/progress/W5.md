# W5 progress: agent change review

Branch `claude/fyx-w5-agent-review-45eb11`. Phase A (model + hook) done; Phase B waits for W3's container.

## Where agent edits enter Zed today

- **Permission.** An ACP agent's `session/request_permission` lands in `AcpThread::request_permission`
  (v2 generic) or `request_tool_call_authorization*` → `install_tool_call_authorization` (legacy, what
  external v1 agents such as Claude Agent use). Either emits `AcpThreadEvent::ToolAuthorizationRequested`;
  the conversation view renders the options and calls `authorize_permission_request` /
  `select_permission_option`. For an edit tool the tool call's content holds the proposed diff:
  `ToolCallContent::LegacyDiff { source: acp_v1::Diff { path, old_text, new_text } }` (v1; for Claude's
  `Edit` tool `old_text`/`new_text` are fragments, not whole files) or `ToolCallContent::Diff` (v2, patch
  based).
- **The write.** After consent the agent calls the client's `fs/write_text_file`, handled by
  `AcpThread::write_text_file`: it diffs the buffer snapshot against the new content (`text_diff`),
  applies it in one agent transaction, reports to the `ActionLog` (`buffer_read` / `buffer_edited`),
  formats and saves. Nothing on this path asks the user; the hunk-level control Zed offers is after the
  fact: `ActionLog::keep_edits_in_range` / `reject_edits_in_ranges`, driven by `agent_ui::agent_diff`
  (`AgentDiffPane`, editor toolbar Keep/Reject).

## Design

1. **Write gate (authoritative).** The only point where the host can guarantee which hunks land is the
   write itself, because the host performs it. Hook in `AcpThread::write_text_file`: before the buffer
   is touched, `acp_thread::fyx_review::gate_agent_write` hands `{session, path, buffer, old_text,
   new_text}` to a host-installed `AgentWriteGate` (a GPUI global; none installed → upstream behaviour)
   and awaits an outcome:
   - all hunks accepted → write the agent's content unchanged;
   - partial → write the old text with only the accepted hunks applied, then return an error to the
     agent that lists rejected hunks and comments ("applied 1 of 2 hunks … re-read the file"), so an
     agent never believes an edit landed that did not;
   - all rejected, review cancelled, or the gate dropped → write nothing, return the feedback as error
     (fail closed).
   The rest of `write_text_file` is unchanged, so the action log, `AgentDiffPane`, format-on-save and
   save keep working on whatever landed.
2. **Permission previews.** `agent_review::init` uses `cx.observe_new::<AcpThread>` to subscribe to every
   thread's `ToolAuthorizationRequested` without an upstream edit. When review mode is on and the tool
   call carries a v1 diff, the host opens a *preview* review of that diff. Resolving it answers the
   permission in the host: every hunk rejected → the request's `RejectOnce` option, otherwise
   `AllowOnce`. Decisions carry over to the write gate by content (same path, same old/new lines); any
   hunk of the actual write that was not decided in the preview (fragments that start mid-line, format
   changes, extra edits) is held for review again. If the permission is answered elsewhere first, the
   undecided preview is dropped.
3. **Host model (`crates/agent_review`).** `ProposedEdit`: hunks from `language::line_diff` (Zed's
   existing imara-diff line diff), per-hunk `Pending | Accepted | Rejected` and comment, `resolution()`,
   `apply_accepted()`, `feedback()`. `AgentReview` (global entity): review mode, open reviews, decision
   and comment setters, `submit`, events `ReviewOpened/Updated/Resolved` for the UI and for observers.
4. **Consent stays in the host.** The decision API lives on the host entity only. Extensions get the
   `agent:review` capability later as observe-only (events + read accessors); nothing in the WIT can
   resolve a review.
5. **Review mode** defaults to off in phase A: without the phase B UI a gated write would wait forever.
   Phase B turns it on behind the feature flag together with the UI.

Not rebuilt: diffing (`language::line_diff` / `text_diff`), applying (the existing `write_text_file`
path), post-hoc keep/reject (`ActionLog` + `AgentDiffPane`), and for phase B the diff view
(`acp_thread::Diff` multibuffer + `buffer_diff`, as the conversation view already renders).

## Upstream surface

- `crates/acp_thread/src/acp_thread.rs`: `mod fyx_review` + re-export, two marked spots in
  `write_text_file` (gate before the edit, feedback after the save).
- `crates/acp_thread/src/fyx_review.rs`: new file in the upstream crate (gate trait + global), so rebases
  never conflict on it.
- No `Cargo.toml` change in `acp_thread`; `agent_review` depends on `acp_thread`, not the reverse.

## Phase B (after W3)

Review panel in W3's container: one `Diff`-backed multibuffer per review, hunk keyboard routing while
review mode is active (accept / reject / comment / next / submit), `agent_review::init` called from
`crates/zed` (integrator), review mode on behind the feature flag.
