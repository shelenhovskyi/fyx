- **P5 5.13 (done): extension proposals** for W3's `fyx:ui` 0.4 `review.propose` bridge in `ui_ext_host`.
  - `AgentReview::propose(ExtensionProposal { write: AgentWrite, extension, title }, cx) -> Proposal { id, outcome }`.
    The id is handed out at once. `outcome: Task<Result<ProposalOutcome>>` fails when the review closes undecided.
    Dropping it closes the review.
  - Forced review: it opens with review mode off. Auto-accept never applies (user patterns, project rules, "accept
    all in turn"). `deny` rejects it at once with feedback and opens nothing; "reject all in turn" rejects it.
  - `ProposalOutcome { decision: ProposalDecision (Accepted/Partial/Rejected), resolution, content, final_content,
    feedback }`. `final_content` is the old text plus accepted hunks. Users decide hunks; they cannot edit the text.
  - `review_text(id)` returns the current text (accepted so far). `withdraw(id) -> Result<String>` closes an
    undecided extension review, including one not yet open, and returns that text. It refuses agent reviews.
  - `ReviewSource::Extension { name, title }`; `ReviewSource` is no longer `Copy` and `Review::source()` returns
    `&ReviewSource`. The pane shows "Proposed by <name>: <title>". In the observe snapshot it is
    `ObservedSource::Write`, because W3's `agent_observe` matches exhaustively. A new variant would need W3 to
    switch over.
  - `review_write` and `AgentWriteOutcome` (acp_thread) are unchanged. The resolution is on `ProposalOutcome`,
    because `acp_thread` cannot see `agent_review::Resolution`.
  - Internally, held writes now receive the decided `ProposedEdit` (`Responder::Write`). `hold` takes a
    pre-allocated id and a source.
