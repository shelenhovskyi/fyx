## Handoff (2026-11-20, after P7 7.2 and 7.3)

- Owns `crates/agent_review` and the W5 files in upstream crates: `acp_thread/src/fyx_review.rs`,
  `agent/src/tools/edit_session/fyx_review.rs`, `agent/src/tools/fyx_file_operations.rs`.
- **7.2 review comments to the agent** (`review_comments.rs`):
  - A comment on a rejected hunk stays in the decision feedback. A comment on an accepted hunk is no longer in
    it (also not in `ProposalOutcome.feedback`): it stays open per session until "Send comments to agent"
    (`agent_review::SendComments`, ctrl-k shift-c) or goes in front of the user's next prompt
    (`take_prompt_notes`). Comments on still-open reviews can be sent too (`Hunk::comment_sent`).
  - Native thread: `AcpThread::send` at once when idle, queued until `Stopped` when generating, open again on
    `Error`/`ConnectionLost`. One prompt, `path:line` relative to the project, an excerpt of the change.
  - Extensions: `take_extension_comments(name) -> Vec<CommentBatch>` on `AgentReviewEvent::CommentsChanged`.
    W3 wires it into `ui_ext_host`; W0 stages `io-event::review-comments` (exact WIT in
    `docs/fyx/wit-0.4/design.md` §B.10, "Review comments"). The extensions then answer the next relay hook
    with `additionalContext` (or `Stop` → `decision: block`).
- **7.3 guardrails** (`secret_scan.rs`): the lines an agent edit adds are scanned for known key formats
  (AWS, GitHub, GitLab, Slack, Anthropic, OpenAI, Stripe, Google, npm, private keys) and high-entropy values
  assigned to secret names. A finding holds the edit for review even with review mode off
  (`scan_secrets`, on in `init`, off in `AgentReview::default`), and neither "accept all in turn" nor
  `auto_accept` accepts it; "reject all in turn" still rejects. The pane shows the masked findings in red.
  Protected paths (`always_ask`) were never auto-accepted; `.env` and account dirs stay out of agent context
  through `fyx_guard` (W2c).
- Cost: with the scan on, every agent write goes through the gate (diff off the main thread) also with
  review mode off.
- Not done: a dev-build check of both features in the real app; a setting to turn the scan off.
