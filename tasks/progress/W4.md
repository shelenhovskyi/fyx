## SDK surface (`crates/ui_ext_sdk/src/ui_ext_sdk.rs`)

- `Extension` trait (`new`, `surfaces`, `mount`, `handle_event`, `list_rows`; the last two have
  defaults) and `register_extension!(Type)`, which implements the generated `Guest` and calls the
  generated `export!`. The instance lives in a thread local, created on the first call.
- `TreeBuilder`: nested closures (`column`, `row`, `flex`, `container`, plus leaf helpers `text`,
  `button`, `input`, `list`, `table`, `icon`, `markdown`, `diff_view`) produce a flat, parents-first
  `Vec<Node>`; every node gets an id from an `IdAllocator` (monotonic, starts at 1).
- Props builders as inherent impls on the generated records (`FlexProps::column().gap(8)`,
  `TextProps::new("x").bold()`, `ButtonProps::new("+").style(ButtonStyle::Filled)`, ...) and
  `From<â€¦Props> for Props`. `Surface::panel` / `Surface::status_item`.
- `PatchSet`: `set_props`, `insert`, `insert_subtree` (top-level nodes get `before`, deeper ones
  append), `remove`, `into_update` (`unchanged` when empty).
- `SurfaceTree`: the extension's mirror of one surface. `mount` / `replace` build a tree; `set_props`
  queues a patch only when props changed; `insert`, `remove`, `clear_children`, `rebuild` (same
  position, new ids); `set_props_from_host` for values the host already shows (typed input text);
  `take_update` hands the queue to `handle-event` or `push_update`. Errors are `TreeError`, which
  converts into the WIT `string` error with `?`.
- `list_rows(start, count, row_count, build_row)` / `list_row` / `row_range` for `list-rows`.
- `log` and `push_update` wrap the host imports. Off WASM (unit tests) `log` prints to stderr and
  `push_update` is recorded for `take_pushed_updates()`, because wit-bindgen's off-WASM import stubs
  are `unreachable!()` inside `extern "C"` and abort the test process.

## Notes for W2 / W3 (host side)

- **WASI imports.** Both components import WASI 0.2.9 (`wasi:cli/*`, `wasi:io/*`,
  `wasi:clocks/monotonic-clock`, `wasi:random/insecure-seed`) because Rust std on `wasm32-wasip2`
  pulls them in. The host linker needs `wasmtime_wasi` added (as Zed's extension host already does).
  For the same reason `wasm-tools component targets crates/ui_ext/wit <wasm> --world ui-extension`
  fails with `missing import named wasi:io/poll@0.2.9`; `component wit` shows the `fyx:ui` part is
  exactly the frozen world.
- **Unused imports are dropped.** The counter and todo components import only `host.log`, not
  `push-update`, since neither calls it. A host linker that defines both functions is fine.
- **Row node ids.** Rows are built with row-local ids starting at `0x8000_0000`
  (`ROW_NODE_ID_BASE`), unique only within one row; main-tree ids count up from 1. Assumption: the
  host scopes row subtrees by `(list node, index)` and does not merge row ids into the surface's id
  space. Tell W4 if the host needs surface-unique row ids.
- **Row refresh.** There is no "rows changed" patch. The SDK assumes the host re-requests visible
  rows when a list node's props change (the counter relies on that: `row-count` changes on every
  click). When rows change but the props do not (todo filter with the same match count), the todo
  demo uses `SurfaceTree::rebuild` on the list, i.e. `remove(old list)` + `insert(new list id)`, and
  ignores `list-rows` for the old id. A WIT-level `invalidate-rows(node-id)` patch would be cheaper
  and keep the scroll position; candidate for 0.2.
- **Input echo.** On `input-changed`, the todo demo does not echo the value back as `set-props`
  (it would fight the cursor); it records it with `set_props_from_host`. The host should treat the
  input's text as owned by the user while focused.
- **Icons** used: `hash`, `dash`, `plus` (counter), `list_todo`, `rotate_cw` (todo): snake_case
  names of Zed's `IconName`; the host decides the mapping.

## Proposal: how the host discovers a UI extension

Add a `[fyx_ui]` table to `extension.toml` (upstream's `ExtensionManifest` has no
`deny_unknown_fields`, so Zed ignores it and a Fyx extension stays installable there):

```toml
id = "fyx-demo-counter"
name = "Counter demo"
version = "0.1.0"
schema_version = 1

[fyx_ui]
# The fyx:ui world the component implements; the host refuses versions it does not know.
api_version = "0.1.0"
# Component path inside the extension directory. Separate from `extension.wasm`, so one extension
# can ship a classic Zed component and a UI component side by side, each in its own Store.
component = "fyx_ui.wasm"
# Capabilities the host must grant before instantiating (ARCHITECTURE.md layer table).
capabilities = ["ui:panel"]
```

The host instantiates the component only when the table is present, calls `surfaces()` once and
registers the panels / status items it returns. Surfaces are deliberately not duplicated in the
manifest; if the host needs them before instantiating (lazy loading), add
`surfaces = [{ id = "counter", kind = "panel" }]` later. Not implemented host-side (W2/W3 own it).
