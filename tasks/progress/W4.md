## Platform task 2.4, part 2: the harness runs fyx:ui 0.2 components (2026-11-18)

`fyx_ext_harness` loads 0.1 and 0.2 components (`SUPPORTED_API_VERSIONS`). The host semantics
mirror W2c's 0.2 host, from its uncommitted work in `ui_ext_wasm` (`effects.rs`,
`fyx_ui_v0_2.rs`, `dispatch.rs`, `ticks.rs`, read on 2026-11-18). Both build on `ui_ext::LiveIds`
for ids, caps and capabilities. The harness has its own Apache implementation, in
`crates/fyx_ext_harness/src/api_state.rs`.

- **One internal model:**
  - Every call goes through the 0.2 model (`ui_ext::v0_2`), as in W2c's `dispatch.rs`.
  - The existing 0.1-typed API is unchanged. For a 0.1 component it is lossless; for a 0.2
    component it is the host's 0.1 view (`shim`).
  - Trees are validated by `ui_ext::Tree`, through the 0.1 shim, as the host does.
  - The full 0.2 props of every node are kept beside the tree.
- **0.2 host imports:**
  - each import is checked when it is called and its effect applied after the call, in order,
    before the reply, also after an `Err` (design.md, A);
  - `push-update` returns errors: unknown surface, more than 64 pushes, the tree caps, and more
    than 2 × 16384 patches and nodes per call;
  - ticks are clamped to 100 ms and capped at 24 h;
  - a modal needs a click or Enter: during the call, or within 5 s after it, once;
  - add/remove/show/hide follow E and C; decorations follow L, with 512 decoration changes per
    call.
- **What the renderer does, as far as a test can see it:**
  - typed text, and the `row-selected` selection, are written into the tree first;
  - a shown modal mounts after the call, and closing it drops its tree and tick;
  - a push or decoration whose tree does not fit remounts it; a decoration whose remount fails is
    removed, with a `warn` log;
  - `dismissed` drops the tree first, and its reply is not applied;
  - `invalidate-rows` must target a list or table, and it counts as touching it;
  - three failed ticks in a row stop a surface's ticks until an event on it.
- **New API:**
  - loading: `load_with_capabilities`, `ALL_CAPABILITIES`, `ui_api_version`;
  - events and rows: `event_v0_2`, `click_v0_2`, `handle_event_raw_v0_2` (`RawEffects`),
    `rows_v0_2`;
  - the tree: `props_v0_2`, `nodes_v0_2`, `surfaces_v0_2`;
  - effects: `effects()` (`HostEffect`, the same variants as W2c's);
  - ticks and modals: `tick`, `pending_tick`, `dismiss`, `is_shown`;
  - decorations: `decoration`, `decorations`;
  - results: `Outcome { effects, update, touched, invalidated }`.

  There is no clock: a test calls `tick(surface)`, which runs the pending tick. Visibility, the
  background minimum and the per-extension tick budget are renderer timing, so they are not
  simulated.
- **Fixture:** `crates/fyx_ext_harness/fixtures/v0_2`, a 0.2 guest written with the SDK. It has
  its own workspace and lockfile, and its doc comment lists its node ids. It covers:
  - ticks and failing ticks;
  - the modal: gesture, selection, submit, close, dismiss, and opening from a tick;
  - add and remove surface, then a push to the removed one;
  - decorations: place, event, remove, a misfit, and without the capability;
  - `invalidate-rows`, indent and the push cap.

## Platform task 1.8: the test harness and `fyx-ext test` (2026-11-18)

**`crates/fyx_ext_harness`** is the spec's `fyx_sdk::testing`. It is Apache-2.0 and host-only, so
the SDK never pulls in wasmtime and authors' test dependencies stay Apache. It does not depend on
`ui_ext_wasm` (GPL).

- **What it does:** `Harness::load` / `load_file` / `from_env` (`FYX_EXT_COMPONENT`) runs a
  component in wasmtime without GPUI. Then:
  - `surfaces()`, `mount()`, `event()`, `rows()`;
  - `handle_event_raw()`, the call as the host runtime returns it;
  - lookups: `tree()`, `text()`, `find()`, `find_text()`, `find_button()`, `click()`;
  - records: `pushed()`, `logs()`, `disabled()`.
- **Fidelity:**
  - Trees, patches, limits and validation are `ui_ext`'s (`Tree::from_nodes`, `from_row`,
    `apply_update`, `TreeLimits`), not copies.
  - The call contract is reimplemented, not copied:
    - WASI p2 with stderr only;
    - a 2 s budget for instantiation and `surfaces()`, then 200 ms per call, enforced by epoch;
    - more than 64 pushes traps;
    - a trap or an overrun disables the instance;
    - pushes apply in order before the reply;
    - rows must be in the requested range;
    - the version section is read, with the import fallback.
  - Typed text is written into the input before `input-changed` / `input-submitted`, as the
    renderer does.
  - One known difference: a guest blocked inside a WASI call such as `thread::sleep` stops only
    when it returns to WebAssembly. The host's async runtime stops waiting at the deadline.

extension's own crate, so the linker cannot drop it as an unreferenced member of the SDK rlib; it is
wasm32-only. `wasm-tools objdump` on both demo components shows it once, inside the core module:

```

fyx_demo_todo.wasm:       custom "fyx:ui-api-version" | 0x39d196 - 0x39d19c | 6 bytes | 1 count
```

Both read back as `[0, 0, 0, 1, 0, 0]`. Test `api_version_matches_the_wit_package` checks the bytes and

## SDK surface (`crates/ui_ext_sdk/src/ui_ext_sdk.rs`)

- `Extension` trait (`new`, `surfaces`, `mount`, `handle_event`, `list_rows`; the last two have
  defaults) and `register_extension!(Type)`, which implements the generated `Guest` and calls the
  generated `export!`. The instance lives in a thread local, created on the first call.
- `TreeBuilder`: nested closures (`column`, `row`, `flex`, `container`, plus leaf helpers `text`,
  `button`, `input`, `list`, `table`, `icon`, `markdown`, `diff_view`) produce a flat, parents-first
  `Vec<Node>`; every node gets an id from an `IdAllocator` (monotonic, starts at 1).
- Props builders as inherent impls on the generated records (`FlexProps::column().gap(8)`,
  `TextProps::new("x").bold()`, `ButtonProps::new("+").style(ButtonStyle::Filled)`, ...) and
  `From<…Props> for Props`. `Surface::panel` / `Surface::status_item`.
- `PatchSet`: `set_props`, `insert`, `insert_subtree` (top-level nodes get `before`, deeper ones
  append), `remove`, `into_update` (`unchanged` when empty).
- `SurfaceTree`: the extension's mirror of one surface. `mount` / `replace` build a tree; `set_props`
  queues a patch only when props changed; `insert`, `remove`, `clear_children`, `rebuild` (same
  position, new ids); `apply_event` mirrors the host's own write of typed input text (call it
  first in `handle-event`); `set_props_from_host` for other values the host already shows;
  `take_update` hands the queue to `handle-event` or `push_update`. Errors are `TreeError`, which
  converts into the WIT `string` error with `?`.
- `list_rows(start, count, row_count, build_row)` / `list_row` / `row_range` for `list-rows`.
- `log` and `push_update` wrap the host imports. Off WASM (unit tests) `log` prints to stderr and
  `push_update` is recorded for `take_pushed_updates()`, because wit-bindgen's off-WASM import stubs
  are `unreachable!()` inside `extern "C"` and abort the test process.

## Notes for W2 / W3 (host side)

- **WASI imports.** Both components import WASI 0.2.9 (`wasi:cli/*`, `wasi:io/*`,
  `wasi:clocks/monotonic-clock`, `wasi:random/insecure-seed`) because Rust std on `wasm32-wasip2`
  pulls them in. The host linker needs `wasmtime_wasi` added (as Zed's extension host already does).
  For the same reason `wasm-tools component targets crates/ui_ext/wit <wasm> --world ui-extension`
  fails with `missing import named wasi:io/poll@0.2.9`; `component wit` shows the `fyx:ui` part is
  exactly the frozen world.
- **Unused imports are dropped.** The counter and todo components import only `host.log`, not
  `push-update`, since neither calls it. A host linker that defines both functions is fine.
- **Row node ids.** Rows are built with row-local ids starting at `0x8000_0000`
  (`ROW_NODE_ID_BASE`), unique only within one row; main-tree ids count up from 1. Assumption: the
  host scopes row subtrees by `(list node, index)` and does not merge row ids into the surface's id
  space. Tell W4 if the host needs surface-unique row ids.
- **Row refresh.** There is no "rows changed" patch. The SDK assumes the host re-requests visible
  rows when a list node's props change (the counter relies on that: `row-count` changes on every
  click). When rows change but the props do not (todo filter with the same match count), the todo
  demo uses `SurfaceTree::rebuild` on the list, i.e. `remove(old list)` + `insert(new list id)`, and
  ignores `list-rows` for the old id. A WIT-level `invalidate-rows(node-id)` patch would be cheaper
  and keep the scroll position; candidate for 0.2.
- **Input echo.** On `input-changed`, the demos do not echo the value back as `set-props` (it
  would fight the cursor). `SurfaceTree::apply_event` writes the typed value into the mirror, as
  the host writes it into its tree (W3 `set_input_locally`).
- **Icons** used: `hash`, `dash`, `plus` (counter), `list_todo`, `rotate_cw` (todo): snake_case
  names of Zed's `IconName`; the host decides the mapping.

## Proposal: how the host discovers a UI extension

Add a `[fyx_ui]` table to `extension.toml` (upstream's `ExtensionManifest` has no
`deny_unknown_fields`, so Zed ignores it and a Fyx extension stays installable there):

```toml
id = "fyx-demo-counter"
name = "Counter demo"
version = "0.1.0"
schema_version = 1

[fyx_ui]
# The fyx:ui world the component implements; the host refuses versions it does not know.
api_version = "0.1.0"
# Component path inside the extension directory. Separate from `extension.wasm`, so one extension
# can ship a classic Zed component and a UI component side by side, each in its own Store.
component = "fyx_ui.wasm"
# Capabilities the host must grant before instantiating (ARCHITECTURE.md layer table).
capabilities = ["ui:panel"]
```

The host instantiates the component only when the table is present, calls `surfaces()` once and
registers the panels / status items it returns. Surfaces are deliberately not duplicated in the
manifest; if the host needs them before instantiating (lazy loading), add
`surfaces = [{ id = "counter", kind = "panel" }]` later. Not implemented host-side (W2/W3 own it).
