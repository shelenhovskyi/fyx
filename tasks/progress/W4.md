**Plan 5.10, done (headless only):**
- **SDK:** the feature `fyx-ui-0-4` (implies `fyx-ui-0-3`) switches the bindings to
  `since_v0.4.0`, so `register_extension!(T)` exports 0.4. Exports as 0.2 and 0.1 still work;
  a 0.4 build cannot export 0.3.
  - `ui_ext_sdk::terminals` wraps every `terminals` import, with builders for the requests and
    the status, and `TreeBuilder::terminal(handle)`.
  - Off WASM the calls record `HostEffect::Terminal`.
  - In 0.2 and 0.1 exports each call is `unavailable` and a terminal node is an error.
- **Harness:** `v0_4.rs` (a copy of `v0_3.rs` plus `terminals`) runs 0.4 components; the other
  0.4 interfaces trap. The fakes are in `terminals.rs`:
  - A pseudo-terminal keeps the output it is given. Tests drive it with
    `type_into_terminal`, `resize_terminal`, `terminal()`, `plain_output()` and
    `terminal_nodes()`.
  - A created terminal follows the `[[fyx_ui.terminal_programs]]` rule, read by
    `load_package`, and echoes `send-input`. `exit_terminal` ends it.
  - The T3 read and write requests are `unavailable`.
  - The model has no terminal node, so a monospace text node `fyx-terminal-node:<handle>`
    stands for one. W2c should add `Props::Terminal` to `ui_ext::v0_2`.
- **Demo `extensions/fyx_demo_pseudo_terminal`** (0.4 only, a placeholder otherwise): a small
  shell in a panel `terminal` node, with Busy and Idle status buttons. It passes `fyx-ext check`;
  `tests/demos_v0_4.rs` runs it headless.
- **`fyx-ext`:** 0.4 capabilities no longer warn as unused.
- **Integrator lines for W0:** the root `Cargo.toml` member
